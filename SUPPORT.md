# Support and community

TuckBit is an open-source **developer preview**. Community help is best-effort; there is no guaranteed support or security-response SLA.

## Where to ask

- **How do I install or use TuckBit?** Start with the [README](README.md), [installation/testing guide](docs/TESTING.md), or the [documentation hub](docs/wiki/Home.md). For a question, use [GitHub Discussions](https://github.com/MakeItEzzz555/tuck-bit/discussions).
- **Something is broken:** Check [existing issues](https://github.com/MakeItEzzz555/tuck-bit/issues), then [open a bug report](https://github.com/MakeItEzzz555/tuck-bit/issues/new/choose) with a *synthetic*, minimal reproduction, environment/version details, and exact validation outcomes.
- **Benchmark or compatibility evidence:** Use the [evaluation report template](https://github.com/MakeItEzzz555/tuck-bit/issues/new/choose) and the [public benchmarking protocol](docs/PUBLIC_BENCHMARK_PROTOCOL.md).
- **Features and ideas:** Open an issue or Discussion before implementing a large change; see [CONTRIBUTING.md](CONTRIBUTING.md).
- **Vulnerabilities:** **Never open a public issue.** Follow [SECURITY.md](SECURITY.md) and use [private vulnerability reporting](https://github.com/MakeItEzzz555/tuck-bit/security/advisories/new).

## Privacy checklist

Do not post credentials, private repositories, raw agent transcripts, proprietary prompts, model session dumps, environment variables, host filesystem inventories, personal identifiers, or hidden graders. Prefer minimal synthetic fixtures and sanitized numeric/categorical results. Redact **before** sharing; deleting a public comment later may not remove it from caches.

## Scope and limitations

TuckBit does not control an AI host's tool permissions, provide a security sandbox, silently run agents, or guarantee reduced cost/tokens. An offline passing test is not proof of real-agent performance.
